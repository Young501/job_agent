# Job Agent

当前 Agent 版本：`v1.1.0`。LinkedIn 与 SEEK Worker 为 `v1.1.0`，Indeed Worker 的 Job Type 修复版为 `v1.1.1`。

## 项目简介

Job Agent 是一个在本机运行、以**广覆盖和避免遗漏**为优先目标的求职检索与审阅工具。它适合使用较宽泛的关键词搜索 LinkedIn、Indeed 和 SEEK，尽可能收集完整结果，再通过职业画像、职位名初筛、完整 JD 和 AI 匹配逐层缩小审阅范围。与只展示少量推荐结果的求职 Agent 相比，本项目更重视结果覆盖率和可追溯性，当前核心原则是：**宁可保留重复，也不要因为过早去重或判断失败而漏掉职位机会。**

三个平台都由 Tampermonkey Worker 在用户已经登录的真实浏览器页面中完成搜索与读取，而不是由服务器直接批量请求招聘网站。这样可以沿用正常浏览器访问路径，降低后台抓取触发访问限制的风险，也允许用户在登录、验证码或页面变化时及时介入。系统同时提供访问节流、任务串行、失败保留、JD 补取、历史结果复用和人工确认等多层保护。

Agent 不会自动投递职位，也不会尝试绕过登录、验证码或平台安全检查。遇到需要人工处理的页面时，任务会暂停并等待用户继续。

## 当前工作流

```mermaid
flowchart TD
    A["建立多个职业画像<br/>职业求职、兼职等不同目标"] --> B["选择任务组合<br/>平台、关键词、地点、时间、职位类型"]
    B --> B1["选择本次运行画像<br/>固定画像、偏好与排除词快照"]
    B1 --> C["统一预检<br/>实际验证平台搜索条件"]
    C --> D["按顺序运行任务<br/>LinkedIn、Indeed、SEEK"]
    D --> E["Worker 扫描职位卡片<br/>宽范围收集，失败不丢弃"]
    E --> F["Agent 统一入库<br/>保留平台、任务与执行时间"]
    F --> G{"统一历史中是否已有<br/>高置信度重复职位"}
    G -->|"是"| H["记录本次重复出现<br/>同画像复用审阅，跨画像只复用 JD"]
    G -->|"否"| I{"标题或卡片摘要<br/>是否明确不相关"}

    I -->|"否或不确定"| K["自动获取完整 JD<br/>后台读取，失败可集中补取"]
    K --> L["Agent 结合职业画像进行 AI 审阅<br/>能力、方向、身份与签证"]
    L --> M["输出匹配分数、分数构成<br/>Strong、Maybe、Low、Rejected"]
    J --> N["人工职位审阅"]
    M --> N
    N --> O["标记已看、有用或没用<br/>纠正错误分类并补充原因"]
    O --> P["完成本次审阅并复盘"]
    P --> Q["生成偏好信号与待审核排除词<br/>用户确认后用于后续任务"]
    Q --> B
    M --> S["按需生成 Cover Letter<br/>修改、保存版本、导出 PDF"]
    R["统一本地历史<br/>任务、JD 与 AI 结果"] --> G
    R --> L

```

每次任务都形成独立运行批次，可以在“职位审阅”继续处理未看职位，也可以按任务和执行时间回到历史记录。三个平台扫描到的职位会先进入 Agent 的同一份本地历史，再决定是否获取 JD 和调用 AI。平台原始 ID、链接、运行批次和处理状态始终保留，方便追溯、重试和删除某一轮运行后重新判断。

随着使用次数增加，每套画像会分别形成更准确的偏好模型；经用户批准的排除关键词会减少明显无关职位，职位名初筛会减少不必要的完整 JD 获取，历史 AI 结果也会在同一画像下复用。因此，系统的目标是让后续筛选更符合用户需求，并在同等搜索范围下逐步减少不必要的 AI 调用和 token 消耗。

## 最快打开方式

需要先安装 [Node.js](https://nodejs.org/) 18 或更高版本。

在 PowerShell 中运行：

```powershell
cd C:\path\to\job_agent
npm start
```

看到下面的信息后，保持这个 PowerShell 窗口打开：

```text
Job Agent is running at http://127.0.0.1:4317
```

然后在浏览器打开：

<http://127.0.0.1:4317>

日常再次使用时，只需要进入项目目录运行 `npm start`，再打开上面的地址。关闭运行 `npm start` 的终端或按 `Ctrl+C` 即可停止服务。

## 首次安装

```powershell
git clone https://github.com/Young501/job_agent.git
cd job_agent
npm start
```

这个项目目前没有第三方 Node.js 依赖，因此不需要额外执行 `npm install`。

启动面板后：

1. 在 Chrome 中安装 Tampermonkey。
2. 打开 Job Agent 左侧的“安装设置”。
3. 点击一键安装，或分别安装 LinkedIn、Indeed、SEEK Worker。
4. 在 Tampermonkey 安装页面确认安装。已有同一 Worker 的旧版本会被覆盖。
5. 保持三个平台处于登录状态。

Worker 只有在 Job Agent 发出预检或运行任务时才会自动操作网页。平时正常浏览招聘网站不会开始扫描。

Tampermonkey 会按相同脚本名称覆盖旧版 Worker；更新脚本不会清空 Agent 的统一本地历史。

## PDF 简历

`.txt`、`.md` 和 `.docx` 可以直接读取。读取文字型 PDF 还需要 Python 3 和 `pypdf`：

```powershell
python -m pip install pypdf
```

如果系统中的 Python 命令不是 `python`，可以在 `.env` 中指定：

```dotenv
JOB_AGENT_PYTHON_PATH=C:\path\to\python.exe
```

扫描版 PDF 没有可提取文字时，可将简历内容粘贴到文本框，或使用职业画像页面提供的 GPT Prompt，在 ChatGPT 中生成画像 JSON 后粘贴回来。

## 配置 AI

AI 是可选的。不配置时，职位名筛选、基础 JD 筛选和复盘仍可使用本地规则运行。

推荐直接在“搜索设置 -> AI 服务”中填写：

- Base URL：OpenAI 兼容接口的地址，通常以 `/v1` 结尾。
- Model：接口支持的模型名称。
- API Key：对应接口的密钥。
- API 格式：根据服务选择 Responses API 或 Chat Completions。

先点击“测试连接”，成功后再点击“保存 AI 配置”。API Key 只保存在本机的 `data/ai-config.json`，不会回显到页面，也不会提交到 Git。

也可以复制 `.env.example` 为 `.env` 后通过环境变量配置。默认已限制输入长度、输出 token 和单次运行调用次数。

## 每日使用流程

1. 在“职业画像”点击“新建画像”，输入名称后选择空白开始或复制当前画像内容；也可以在“简历上传”先填写新画像名称，再上传或粘贴简历生成一套新画像。系统会尝试填入基本信息、身份与签证、工作、项目、教育、课外活动、证书、语言、技能和荣誉。所有字段均可留空；可以保留多套画像，例如“Software 求职”和“Casual hospitality”。每套画像有独立的学习偏好、排除关键词和待审核建议，复制画像时也不会复制这些学习数据。
2. 在“每日任务”的统一任务组合区选择内置组合，或创建自定义组合。新组合既可以直接勾选已有的已预检任务，也可以添加尚未预检的新任务，两种来源可以混合保存；组合内会直接显示子任务的预检、启用、今日运行和选择状态，单独添加的任务会自动归入“单独任务”。
   需要多个备选关键词时使用逗号分隔，例如 `intern, internship`。平台搜索第一个词，Worker 会按任一备选词保留职位；不要填写布尔表达式 `OR`。
3. Indeed 和 SEEK 任务还可以选择职位类型。SEEK 支持 Full-time、Part-time、Contract / Temp、Casual；Indeed 支持页面当前提供的 Casual、Part-time、Full-time、Permanent、Temporary、Fixed term、Contract 等类型。LinkedIn 暂时保持“不限”。
4. 对尚未验证的任务执行统一预检。浏览器会实际填写平台、关键词、地点、时间和职位类型条件。
5. 预检成功后点击“开始运行”，先选择本次使用的画像并确认该画像的排除词。运行创建后会保存画像、学习偏好和排除词快照，后续编辑画像不会改变已经开始的这轮评分依据。三个平台严格按顺序执行，不会并行操作同一浏览器。
6. Worker 扫描到职位卡片后，先把当页候选交给 Agent。Agent 立即用统一历史和本地规则返回“跳过、复用、排除或获取 JD”的计划，因此无需先把整份历史复制给脚本。不确定的职位继续保留并进入 JD 流程。
7. AI 会把岗位能力匹配与身份/签证兼容性分开判断，并按完整语义理解多个可选条件；明确不兼容才排除，信息模糊或命中用户强制保留范围时继续保留。同一画像的历史 AI 审阅可直接复用；切换画像后不会复用旧分数，只会复用已有完整 JD 并按新画像重新评分。
8. 登录、验证码或页面异常需要人工处理时，根据运行监控中的提示处理并继续。单条 JD 获取失败不会丢掉该职位，审阅页会明确标注失败状态。
9. 在“职位审阅”查看本次任务统计、自动 AI 评分和处理状态。分数下方的虚线表示可悬浮查看一句评分理由。刷新图标会使用已保存的完整 JD 重新执行 AI 审阅；旧职位缺少 JD 时，文件搜索图标会打开原职位，由对应 Worker 读取完整 JD 后自动继续审阅，不再要求手动粘贴。
   已结束的单项任务统计可以连同其关联职位删除；“运行历史”可以删除整次运行及其关联职位，两者都不会影响每日任务或任务组合。
10. 对已经完成 AI JD 审阅、但判断没有帮助的职位点击“没帮助”，可选“分类错了”或“与我无关”，也可以补充原因。
11. 当日审阅结束后点击“完成本次审阅并复盘”。学习结果只写入这次运行所用的画像，不会影响其他画像，也不会删除任何职位。

## Cover Letter

取得完整 JD 后，职位操作区会显示 Cover Letter 图标。打开后可以：

- 选择任一画像作为事实来源，而不是被迫使用职位最初评分时的画像。
- 设置最多 1–3 页，并修改默认生成 Prompt。
- 基于画像与 JD 生成常见职场格式的英文 Cover Letter；AI 被要求使用自然、低 AI 痕迹的表达，以 STAR 逻辑组织证据但不显示 STAR 标签，并且不得虚构经历或资格。
- 阅读中文概述，直接编辑信件，填写修改建议后生成新版本。
- 保存人工编辑，并通过系统打印窗口导出 A4 PDF。

默认页数和 Prompt 位于“搜索设置 -> Cover Letter”。生成记录保存在本机，并与职位和所选画像关联。

历史职位和复盘结论保存在“历史记录”中。撤销旧反馈后，可以选择对应历史批次重新复盘，以清除已经不适用的偏好。

## 统一历史与去重边界

Agent 运行任务时不再让 Tampermonkey Worker 自行跳过历史职位。更新三个 Worker 后，在“安装设置”点击“迁移并整理历史”，系统会用一个专用窗口依次读取 LinkedIn、Indeed 和 SEEK 的旧 Worker 历史；该流程不会领取任务或启动搜索。服务确认每条旧记录已导入或被统一历史覆盖后，才清理对应 Worker 中的副本。之后所有新职位都在本机 `data/state.json` 中统一判断，三个平台共用同一份历史。

迁移会兼容旧平台 ID、规范链接、字段不完整的记录和早期指纹格式。只有稳定平台 ID、规范链接或完全相同的旧存档 key 才会自动合并；无法可靠对应新职位的早期指纹只作为历史存档保留，不会用于拦截未来职位。

自动去重采用偏保守规则：

- 同一平台的稳定职位 ID 或规范职位链接一致，视为精确重复。
- 跨平台只有在完整职位名、公司名和具体城市或州都一致时，才视为高置信度重复。
- 只有 `Australia` 这类宽泛地点不会用于跨平台自动合并。
- 年份不同的项目、职位名不同的岗位，以及同一平台使用新职位 ID 的重新发布都会保留。
- 无法高置信度确认时继续作为新职位处理；系统宁可保留重复，也不因模糊匹配漏掉机会。

重复职位仍会保存本次任务的出现记录。Worker 不接收整份历史列表，而是把每页职位卡交给本机 Agent 批量判断；这个本地请求开销很小，却避免在三个脚本中维护和同步第二份大型历史。对同一画像，系统会跳过不必要的 JD 和 AI 步骤；对不同画像，已有 JD 可以复用，但旧画像的评分和学习偏好不会复用。若历史只有职位 ID 而没有 JD，新画像仍会继续获取 JD，避免把适合另一求职方向的岗位直接漏掉。

删除某个运行批次时，该批次的出现记录会一起删除，剩余职位会立即重新建立去重关系和统计，因此可以用“删除上一轮运行”回退误操作或中断后的结果。

## 数据与安全

以下内容只保存在本机并已被 `.gitignore` 排除：

- `data/state.json`：任务、职位、多套画像、各画像偏好、Cover Letter 和复盘记录。
- `data/ai-config.json`：AI 服务配置和 API Key。
- `data/uploads/`：临时上传文件。
- `.env`：本机环境变量。

“安装设置”中提供调试用的一键清除功能，会在二次确认后清除 Agent 记录和三个 Worker 的历史。内置预设、自定义任务组合、职业画像、搜索设置和 AI Key 都会保留。

## 常见问题

### 页面打不开

确认运行 `npm start` 的终端仍然打开，并访问 `http://127.0.0.1:4317`。如果端口被占用，先关闭旧的 Node.js/Job Agent 服务再重试。

### 任务一直等待 Worker

确认 Tampermonkey 已启用对应平台的 Job Agent Worker，并刷新平台页面。也可以在“安装设置”重新安装最新版 Worker。

### 预检打开页面后没有继续

检查平台是否已登录、是否出现验证码，以及 Worker 是否启用。处理页面提示后，在每日任务中重新尝试预检。

### AI 不可用

先在“搜索设置”执行连接测试。AI 调用失败时系统会保留职位，并在可以回退的流程中使用本地规则，不会因为一次 AI 错误丢失职位。
